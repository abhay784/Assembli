# Roadmap: Assembli

## Overview

Assembli converts furniture assembly manuals into narrated, step-by-step explainer videos. The pipeline has a strict dependency chain: the scene JSON schema must be locked before templates are built, templates must work against mock data before the LLM is integrated, audio duration must be known before Remotion frame counts are computed, and the full pipeline is wired together only after each stage is independently functional. Four phases follow this natural data-flow order, each delivering a coherent, verifiable capability on the way to a working end-to-end demo.

## Phase Details

### Phase 1: Foundation
**Goal**: The scene JSON schema is locked, Remotion templates render correctly from mock data, and the infrastructure layer (S3 upload, BullMQ worker scaffold, job state) is in place
**Depends on**: Nothing (first phase)
**Requirements**: INGEST-01, INGEST-02
**Success Criteria** (what must be TRUE):
  1. User can drag-and-drop a PDF onto the upload area and the file is accepted or rejected with a clear message (type and size validation)
  2. A valid SceneJSON document (matching the Zod schema) can be fed into the Remotion template and a correctly structured preview renders locally
  3. A job record is created on upload and its status is queryable via the status API
  4. The Zod scene schema is the single source of truth — TypeScript types derive from it and it passes validation for a representative mock scene
**Plans**: 6 plans
Plans:
- [x] 01-01-PLAN.md — Next.js 15 bootstrap, Vitest, shared upload constants (25 MB), Redis compose, ESLint/typecheck
- [x] 01-02-PLAN.md — Zod SceneJSON schema (D-01–D-03), mock fixture, schema Vitest suite
- [x] 01-03-PLAN.md — Remotion 4 compositions from mock SceneJSON; Studio entry (D-04)
- [x] 01-04-PLAN.md — BullMQ worker scaffold + shared `lib/queue.ts` + `dev:worker` script
- [x] 01-05-PLAN.md — POST/GET `/api/jobs`, S3 presigned PUT, enqueue metadata-only jobs
- [x] 01-06-PLAN.md — shadcn upload UI per 01-UI-SPEC; magic-byte PDF check; human verify checkpoint
**UI hint**: yes

### Phase 2: LLM Extraction
**Goal**: The system can parse a real IKEA-style PDF and produce valid, Zod-validated SceneJSON via Claude API, with safeguards against context overflow and retry cost spirals
**Depends on**: Phase 1
**Requirements**: EXTRACT-01, EXTRACT-02, EXTRACT-03
**Success Criteria** (what must be TRUE):
  1. Uploading a real IKEA-style PDF produces a SceneJSON document that passes Zod validation without manual intervention
  2. Each extracted scene includes a confidence score field populated by Claude
  3. PDFs that exceed the token pre-flight threshold are rejected with an informative error before any LLM call is made
  4. Claude output that fails Zod validation triggers a capped retry (max 2) before the job fails gracefully
**Plans**: 4 plans
Plans:
- [x] 02-01-PLAN.md — Extend SceneJSON Zod schema (confidence, tools, warnings), mock, JSON Schema export, Remotion types
- [x] 02-02-PLAN.md — S3 GetObject, pdf-parse page preflight, `CLAUDE_MAX_PDF_PAGES` guard
- [x] 02-03-PLAN.md — Anthropic SDK, `extractSceneFromPdfBuffer` with Zod retry loop (D-08), tests with mocks
- [x] 02-04-PLAN.md — Worker extraction pipeline, PutObject `scene.json`, GET job `sceneKey`

### Phase 3: Audio and Render
**Goal**: Given valid SceneJSON, the system generates ElevenLabs narration for each step and renders a final Remotion video where slide durations are driven by audio length — not hardcoded values
**Depends on**: Phase 2
**Requirements**: VIDEO-01, VIDEO-02, VIDEO-03, AUDIO-01, AUDIO-02
**Success Criteria** (what must be TRUE):
  1. Each assembly step has a narration audio clip generated by ElevenLabs and stored to S3
  2. The rendered video shows exploded-view style part animations per step with text caption overlays and a step counter ("Step N of M")
  3. Narration audio is audibly in sync with visual transitions — slide duration matches audio clip length, not a hardcoded value
  4. A complete MP4 file is produced and stored to S3 at the end of the render stage
**Plans**: 4 plans
Plans:
- [ ] 03-01-PLAN.md — Dependencies (@elevenlabs, @remotion/renderer, ffmpeg-static) + ElevenLabs client wrapper + env
- [ ] 03-02-PLAN.md — S3 binary upload, per-step TTS upload to `uploads/{jobId}/audio/`, duration→frames utilities + tests
- [ ] 03-03-PLAN.md — `RenderInput` Zod, `assembly` composition (audio-driven `Sequence`), worker `render-video.ts` (bundle + renderMedia)
- [ ] 03-04-PLAN.md — Full worker pipeline, path guard, `videoKey` on returnvalue + GET API + ManualUpload + mocked tests
**UI hint**: yes

### Phase 4: Pipeline Integration and Output
**Goal**: The full pipeline runs end-to-end — upload a PDF, watch the job progress, and preview the completed video in the browser
**Depends on**: Phase 3
**Requirements**: OUTPUT-01
**Success Criteria** (what must be TRUE):
  1. User can upload a real IKEA-style PDF and see the pipeline progress through all stages without manual intervention
  2. The completed video is playable in the browser via an HTML5 player immediately after the job completes
  3. A job that fails at any pipeline stage shows a meaningful error state rather than hanging indefinitely
