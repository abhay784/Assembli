# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase UI scope (this contract):** PDF manual upload via drag-and-drop (INGEST-01, INGEST-02) — validation feedback, progress while uploading to S3, and error recovery. **Out of scope for Phase 1 UI:** full multi-stage pipeline progress (deferred to v2 INGEST-03 / Phase 4 per REQUIREMENTS); embedded Remotion preview in Next.js (D-04). After a successful upload, at most a **minimal** acknowledgment that the job exists (aligns with queryable status API — no stepper, no ETA).

**Sources pre-populated:** `.planning/phases/01-foundation/01-CONTEXT.md`, `01-RESEARCH.md`, `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, `CLAUDE.md`. **Greenfield:** no `components.json` or `app/` yet — design system rows describe the **planned** stack at scaffold time.

## Layout & focal point

| Item | Specification |
|------|----------------|
| Page structure | Single primary column, max content width **640px**, centered horizontally on the viewport (`mx-auto`), **64px** (`3xl`) vertical padding top/bottom on `md+` viewports |
| Visual focal point | One **card**-wrapped dropzone occupies the vertical and attention center of the column; page title and one line of supporting copy sit **above** the card only |
| Hierarchy | (1) Display title → (2) one-line body hint → (3) dropzone card → (4) inline validation / progress / errors **inside or immediately below** the card |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **Minimum 44×44px** hit target for the **“Choose PDF from device”** control (button or file-input trigger) — WCAG 2.5.5 Target Size; height/width may be 44px even when internal padding uses `sm`/`md`. **Hairline strokes** (e.g. **2px** dropzone border, **2px** `focus-visible` ring) are **not** layout-spacing tokens — they are exempt from the 4px rhythm.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` | Page background (slate-50) |
| Secondary (30%) | `#ffffff` | Card surface; subtle border `#e2e8f0` (slate-200) |
| Accent (10%) | `#0d9488` | See reserved list below (teal-600) |
| Destructive | `#dc2626` | Error text, error icons, destructive actions only (red-600) |

Accent reserved for: **primary upload action** (filled button: “Upload assembly manual” while file is staged and ready), **focus-visible rings** on interactive controls (2px `ring` using accent at ~40% opacity on neutral fill is acceptable), **determinate progress bar fill** during S3 PUT, **single inline text link** style when linking to help (e.g. max size explanation). **Not** used for: default borders, body text, secondary buttons (use neutral outline), drag-over state fill (use secondary + neutral ring).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Upload assembly manual** (enabled only when a validated PDF is staged; while uploading, same control shows loading/disabled state with **Uploading…** label) |
| Secondary action | **Choose PDF from device** (opens file picker; never label “Browse” alone) |
| Empty state heading | **Drop your assembly manual** |
| Empty state body | **PDF only, up to 25 MB.** Drag a file here or use the button below. |
| Error — wrong type | **This file is not a PDF.** Choose a `.pdf` assembly manual and try again. |
| Error — over size | **This PDF is over 25 MB.** Use a smaller export or compress the file, then try again. |
| Error — not a real PDF | **This file does not look like a valid PDF.** It may be mislabeled; export or save as PDF and try again. |
| Error — presign / network | **We could not start the upload.** Check your connection and try again. |
| Error — S3 upload failed | **Upload failed before finishing.** Check your connection and try again. |
| Success (minimal, post-upload) | **Manual received.** Your job is queued. (Optional: show job id in monospace; **no** pipeline step list in Phase 1) |
| Destructive confirmation | **Discard selected file:** **Discard this PDF?** You can choose a different file afterward. — Confirm: **Discard PDF** / Cancel: **Keep file** |

**Notes:** **25 MB** is the **demo default** called out in `01-RESEARCH.md` Open Questions; PLAN.md may adjust — if the numeric cap changes, update empty-state body and over-size error in sync.

## Upload interaction states (prescriptive)

| State | Visual | Interaction |
|-------|--------|-------------|
| Default | Dashed **2px** border `#cbd5e1`, secondary fill | Drop PDF or click **Choose PDF from device** |
| Drag active (`isDragActive`) | Border **neutral-900** `#0f172a`, background **slate-100** `#f1f5f9` (accent **not** required) | Same as default |
| File staged (valid) | Show filename (Label 14px semibold), file size in Body 16px muted `#64748b`; primary CTA **Upload assembly manual** visible | CTA triggers presign + PUT |
| Uploading | Determinate **Progress** 0–100%; CTA disabled; assistive text **Uploading…** | No duplicate requests |
| Success | Success message + minimal job acknowledgment (see copy table); clear staged file UI | User may upload another manual in a later iteration — Phase 1 may reset dropzone after success |
| Error | `Alert` or inline destructive text + icon; preserve **Choose PDF** affordance | User can pick another file without full page reload |

**Validation (INGEST-02):** Client: `accept` PDF, `maxSize` matching server; **magic-byte** check for `%PDF-` on first slice before calling presign (per RESEARCH). Server remains source of truth for presign policy.
